nginx 설정 파일 내용 (참고용)
----------------------------------------

/etc/nginx/sites-available/sck-homepage

server {
    listen 80;
    server_name localhost;

    root /var/www/sck-homepage;
    index index.html;

    location / {
        try_files $uri $uri.html $uri/ =404;
    }

    error_page 404 /404.html;
    location = /404.html {
        internal;
    }
}

알아두면 좋은 것 (자주 헷갈렸던 부분 정리)
----------------------------------------

[기본 개념]
- out 폴더 = Next.js 가 빌드해서 만든 완성된 정적 웹사이트 파일
- nginx = 웹사이트 파일을 실제로 보여주는 프로그램 (웹서버)
- sudo = "관리자 권한으로 실행" (Windows 의 관리자 권한 실행과 같은 개념)
- 서버는 "설치하면 끝"이 아니라, 계속 켜두고 관리해야 하는 것.
  초기 구축은 시작일 뿐이고 유지보수가 진짜 본체.

[SSH]
- SSH = Secure Shell. 서버의 터미널을 내 PC 화면으로 끌어와 쓰는 것.
  명령이 실행되는 곳도 파일이 있는 곳도 전부 서버. 내 PC 는 창구 역할.
- scp, git push 도 전부 SSH 를 통로로 씀. SSH 하나 뚫으면 나머지가 따라옴.
- 비밀번호 vs 암호문구(passphrase) : 완전히 다른 것
    비밀번호  = 서버에 있는 "계정"의 암호. 서버가 검증
    암호문구  = 내 PC 에 있는 "키 파일"의 암호. 내 PC 가 검증, 네트워크로 안 나감
  화면에 Enter passphrase 가 뜨면 키 인증이 되고 있다는 뜻 (성공 신호)
- 키를 "만든 것"과 "서버에 등록한 것"은 다른 작업.
  ssh-keygen 은 내 PC 에 파일만 만듦. 서버의 authorized_keys 에 넣어야 등록됨.
- authorized_keys 는 "로그인한 계정"이 아니라 "파일이 놓인 경로"가 소속을 결정.
  sck-server-01 로 로그인해서 /home/git/... 에 넣으면 git 계정에 등록된 것임.
- 계정마다 authorized_keys 가 따로 있음. 한쪽에 넣어도 다른 계정은 안 열림.
- ssh-agent = 암호문구를 대신 기억해주는 것. 이게 있어야 자동화가 성립함
  (비밀번호 방식은 사람이 손으로 쳐야 해서 스크립트가 중간에 멈춤)

[git]
- git 은 버전 관리, scp 는 배포. 역할이 다름.
  .gitignore 에 /out/ 이 있어서 git push 해도 완성된 홈페이지는 서버로 안 감.
- git commit 전에 이름표 등록 필요 (인증과는 무관, 그냥 기록용)
    git config --global user.name "..."
    git config --global user.email "..."
- origin = 원격 저장소 주소의 별칭. 매번 긴 주소 안 치려고 붙이는 이름
- VS Code 소스 제어 패널(Ctrl+Shift+G)로 버튼 클릭만으로도 작업 가능.
  출력 창(Ctrl+Shift+U)에서 Git 을 고르면 실제 실행된 명령이 보여서 공부에도 좋음

[권한 - 여기서 제일 많이 막혔음]
- 폴더는 실행 권한(x)이 있어야 "안으로 들어갈 수" 있음.
  chmod -R 644 를 폴더에 걸면 x 가 날아가서 CSS/이미지가 403 이 됨
  -> 폴더는 755, 파일은 644 로 나눠서 줘야 함 (위의 find 명령 참고)
- sudo 를 습관적으로 쓰면 파일 주인이 root 가 되어 나중에 scp 가 막힘.
  시스템 설정(/etc/...)이나 패키지 설치처럼 꼭 필요할 때만 쓸 것
- chmod 는 파일 주인만 실행 가능. "허가 거부"가 나오면 소유자부터 확인
    ls -l 로 소유자 확인 -> sudo chown -R $USER:$USER 로 가져오기

[nginx]
- sites-available = 설정 보관함 / sites-enabled = 실제로 켜진 것
  sites-enabled 에 링크가 있어야 적용됨. default 가 남아있으면 그게 먼저 잡힘
- 응답 코드로 상태 판단
    "Welcome to nginx!"  -> default 가 아직 살아있음
    404 Not Found        -> 설정은 적용됐고 파일이 없는 것
    403 Forbidden        -> 파일/폴더는 있는데 nginx 가 못 읽는 것 (권한 또는 index 없음)
- 설정 바꾼 뒤에는 반드시 sudo nginx -t 로 문법 검사 후 재시작

[터미널 실수 방지]
- 창이 여러 개면 지금 어디인지 헷갈림. 프롬프트로 구분할 것
    PS C:\...\sck_homepage>          -> 내 PC
    sck-server-01@sck-server-01:~$   -> 서버 (관리 계정)
    git@sck-server-01:~$             -> 서버 (git 계정)
  헷갈리면 whoami 로 확인
